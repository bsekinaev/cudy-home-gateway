# Удобное наблюдение за интернетом через Telegram

Владелец одобрил последовательный план и выбрал Telegram основным интерфейсом;
веб-интерфейс не нужен. Ниже — конкретизация первого небольшого выпуска.

## Цель

Главная страница должна отличать состояние канала, процесса и правил от
внешней проверки доступа. Недостающая проверка не означает ни успех, ни отказ.
Время обновления экрана не должно подменять время сетевой проверки.

## Подходы

Выбран Telegram на существующих CLI/JSON adapters. Отдельная веб-панель
отложена владельцем. Новые активные probes не добавляются в первый UI-патч:
сначала правильно отображаются уже доступные доказательства.

## Первый выпуск: представление доказательств

- WAN обозначается каналом провайдера, DNS — DNS именно роутера.
- MAIN/Torrent: отдельно состояние службы, configured node и внешний выход.
  Служба берётся из dedicated xray_process, не из aggregate state. Configured
  node не обозначается как active autoswitch node или источник cache probe.
- Внешний выход подтверждается только при state=OK, source=live_probe/cache,
  целочисленном положительном checked_at не из будущего и возрасте <=300 секунд.
  Явный DOWN процесса, aggregate state или WAN запрещает положительный вывод
  по сохранённому egress; DNS DOWN сам по себе не опровергает IP probe.
- Возраст показывается у самой внешней проверки; cache явно обозначается.
  Старые, отсутствующие, неизвестные и некорректные данные дают «не проверен»
  либо «нет свежей проверки». Старый IP не выдаётся за текущий.
  Возраст относится к моменту обновления сообщения, что явно написано на экране.
- REDMI: отдельно правила, Xray, Kill Switch и «Интернет REDMI: не проверен»,
  пока нет независимого клиентского доказательства. Не использовать egress MAIN.
- ASATA обозначается как устройство/правила; Tailscale — как служба.
- Не меняются collectors, notification policy, команды, callbacks, routing,
  user/chat whitelist, Safe Actions или installed runtime.
- JSON schema сохраняется; поля недоверенных текстовых значений ограничиваются.
- ASCII/NUL, Unicode line separators и bidi formatting controls отбрасываются
  в недоверенных текстовых полях; обычный русский текст и emoji сохраняются.
- UI max age 300 с — консервативное решение разработчика, не новая настройка
  владельца; оно может показывать UNKNOWN при более длинном backend TTL.

## Дальнейшая очередь

1. Проверенный путь обновления уже установленного d2039b6 и других модулей.
   Нынешний immutable owner kit рассчитан на исходный baseline и не повторяется.
2. Динамическое обнаружение DNS REDMI по актуальному runtime, ограниченные
   DNS-проверки, freshness в CLI/health. Порт 2004/2007 не зашивается.
3. Приёмка фактической доставки/recovery уведомлений и anti-noise/mute.
4. Краткая сводка и история качества; затем диагностика по кнопке.
5. Только отдельными milestones — Safe Actions и MAIN transactions/rollback.

Полный обрыв связи обнаруживается самим роутером, но Telegram-сообщение возможно
после восстановления. Немедленное внешнее оповещение потребует отдельного watcher.

## Приёмка первого выпуска

Actual ucode poller через поддельную границу gateway/Telegram, без сети:
fresh live/cache, stale source/age, missing/future timestamp, malformed JSON/types,
local DOWN с успешным cache, REDMI policy OK без клиентского доказательства,
неизвестный source и ограничение текста. Существующие navigation/auth regressions
должны оставаться зелёными. Source review и CI до предложения установки.
