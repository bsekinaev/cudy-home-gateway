## Проверка установленной версии 26.11.2026

В PassWall2 26.8.27-r1 run_socks использует eval_set_val, общий TMP_PATH и Lua-генератор /usr/lib/lua/luci/passwall2/util_xray.lua. Указание no_run подавляет запуск в ветке run_socks, но не изолирует генератор от общих данных. Встроенный socks_node_switch ищет процессы по совпадению в командной строке, посылает SIGKILL, удаляет файлы по шаблонам и запускает обновление списка прямых маршрутов. Для проверки кандидатов использовать отдельный генератор с валидируемой схемой входа и имеющийся native supervisor. Изменение MAIN должно идти через проверяемую транзакцию.

На первом этапе очередь уведомлений хранит last_route_results для последней завершённой попытки. Это ограниченный набор состояний без данных Telegram, токена, текста, адресов узлов или ответа сервера. Условие fallback и поведение повторов сохранены. Проверено 43 тестами с имитацией границы curl.

### Конфигурация отдельной проверки кандидата

Добавлен локальный генератор vpn-candidate.uc. Он принимает ограниченный JSON на stdin, строит один SOCKS listener на loopback и один VLESS outbound. Поддержка ограничена RAW, gRPC, XHTTP и известными полями TLS/Reality. Неизвестные поля и отключение проверки TLS отклоняются. Проверка синтетических конфигураций на установленном Xray 26.7.28 прошла для всех трёх транспортов.

Следующая часть того же этапа: снять согласованный снимок разрешённого узла из UCI, запускать генератор с приватным вводом и выводом, связать проверочный порт с принадлежащим процессом, упаковать native supervisor и проверить полное завершение процесса при таймауте. Этот этап открыт до проверки реального HTTPS через изолированный SOCKS.
