# Следующий этап: границы установщика — 21.11.2026

## Подтверждено чтением исходников

- `scripts/owner_series/build_kit.py`: ALLOWED разрешает только dns.sh,
  health.sh, redmi.sh, status.sh и telegram-poller.uc.
- `scripts/owner_series/protocol.uc`: та же граница проверяется на роутере;
  package inventory и непосредственный parent проверяются независимо.
- `scripts/owner_series/parent.py`: PATHS содержит фиксированные 20 файлов;
  CONTROLS отдельно закрепляет 14 файлов механизма развёртывания.
- `scripts/owner_series/engine.uc`: резервирование, запись и восстановление
  опираются на известные inventories и changed; неизвестный runtime отвергается.
- `scripts/owner_series/test_build.py`: отказ для non-observer changes и
  неизвестного runtime — действующий контракт, а не помеха, которую надо убрать.

Таким образом, будущий мониторинг нельзя выпустить простой правкой allowlist
на компьютере. Старые V1/V2 форматы и их проверки остаются неизменными.

## Порядок следующей реализации

1. Составить минимальный closed inventory будущего выпуска и точный delta от
   установленного 62b5c4a: существующие adapters, incidents, notifications, CLI;
   новые файлы и службы допускаются только с явным контрактом жизненного цикла.
2. Определить отдельный versioned профиль пакета, переход от V2, подтверждение
   непосредственного parent и проверку формата на host и router. Не ослаблять V2.
3. До кода записать тесты отказа: лишний файл, неизвестная версия, неверный
   baseline, изменённые controls, несовпадение host/router inventories.
4. Описать создание/удаление файлов при apply/recover/rollback, права и поведение
   при каждом частичном префиксе записи. Удалять можно только принадлежащие
   конкретной операции файлы; чужие файлы и drift блокируют изменение.
5. Отдельно проверить совместимость incident/queue/history: откат runtime не
   перематывает данные. Необратимый формат требует промежуточного совместимого
   выпуска; пока такого изменения не спроектировано и не разрешено пакетом.
6. На OpenWrt VM прогнать kill/reboot между записью, commit, seal и retire;
   старые пакеты и сеансы должны сохранять прежнее поведение. Затем Windows 5.1,
   exact-source CI/native gates, review и отдельный owner-пакет.

Это результат аудита и входные данные инженерного плана, не готовый новый
установщик и не разрешение на запись в CUDY. Следующий runtime ещё не менялся.

## Дальнейшая программа

После установщика: WAN через тот же порт → независимые fresh samples и ранняя
история → уведомления WAN/DNS/MAIN/REDMI → Telegram-диагностика и сводки.
Всё на роутере, без web UI. Один сбой / одно восстановление, круглосуточно;
при полном обрыве отчёт после восстановления. Цель 2–4 минуты требует замера.
История: 7 суток подробно / 30 суток дневных сводок, flush до 15 минут.
Резервный кабель остаётся только аварийным способом доступа.
