## Проверки после восстановления

26.11.2026 на CUDY проверены версия 0.8.0-dev и запущенная служба Telegram.
Home Gateway показал OK для REDMI и Torrent. DNS REDMI на 2007 разрешил
chatgpt.com. На Windows-клиенте в LAN команда ниже получила HTTP 204 от
Google и Cloudflare.

    powershell -NoProfile -File scripts/lan-check.ps1

Команда выдаёт по одному JSON-результату на адрес и возвращает код 1 при
сбое. Для проверки клиентского пути запускайте её с устройства за CUDY
с выключенным клиентским VPN. Результат относится к тому устройству,
на котором запущена команда.

На роутере сохранена приватная копия конфигураций PassWall2, firewall,
DHCP и network. Контрольные суммы всех четырёх файлов проверены.
Резервную копию не помещаем в Git. Восстановление должен репетировать
стенд. Проверки на самом телефоне REDMI и передача легального торрента
остаются отдельными пунктами приёмки.

Далее использовать результаты клиентской пробы в мониторинге. Для
контроллера MAIN сначала включить запись решений в режиме наблюдения.
Перед активацией переключения проверить отсутствие действий при потере WAN,
границы попыток при исчерпании резервов и откат при сбое LAN после смены.

## LAN-подтверждение с Windows-клиента

На коммите 8148bcc Windows-клиент в Wi-Fi с маршрутом через CUDY
выполнил scripts/lan-check.ps1 для уникального токена операции. Google
и Cloudflare вернули HTTP 204. Клиент передал JSON по SSH с проверкой
ключа хоста в тестовую транзакцию. Gateway записал COMMITTED.
Повторная отправка того же ответа вернула 75. SHA256 рабочей конфигурации
PassWall2 до и после совпала.

Эта проверка покрывает реальную LAN-пробу, транспорт и одноразовое
подтверждение. Кандидат применялся к тестовому файлу, а успешный SOCKS
подавался как стендовое условие. Проверка рабочего SOCKS после смены и
перезапуск PassWall2 относятся к отдельной приёмке.
