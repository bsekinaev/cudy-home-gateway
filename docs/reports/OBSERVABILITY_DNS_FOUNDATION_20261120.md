# Начало разработки наблюдения — 20.11.2026

## Что сделано

Изолированная ветка `codex/dns-foundation-20261120`, база `f7bf660`.
Runtime-изменение только `dns.sh`: локальная A-проба учитывает настроенный порт,
TERM через 3 с и KILL через дополнительную 1 с; проверяет форму домена,
доступность applets и нужные возможности клиента. Ошибка инструмента даёт
UNKNOWN; NXDOMAIN, пустой ответ и истечение deadline не дают ложный OK.
Прочие runtime paths и ограничения установщика сохранены.

Проверенный синтаксис BusyBox — `127.0.0.1:port`. В локальном эксперименте
`#port` отклонён до первого пакета, а `:port` получил ответ UDP fixture.
Решение пока не подменяет проверку установленной сборки CUDY.

Созданы [памятка переезда](../WAN_RELOCATION.md) и отдельная
[owner-проверка DNS](../../scripts/observability/README.md). Она читает способности
инструментов и разрешённые поля кандидата `dns-in` из generated config.
Она не устанавливает runtime, не запускает DNS-запросы и не изменяет сеть.
Кандидат из конфигурации не считается подтверждением живого listener.

## Проверки и исправления

- Реальные BusyBox ash/nslookup/timeout и ucode, UDP fixture на loopback,
  контейнер без внешней сети: **13 тестов PASS**.
- Сначала 7 тестов воспроизвели отсутствие новой функции; проверка configured
  port отдельно воспроизвела DOWN на прежнем адаптере при рабочем resolver fixture.
- Независимый review выявил неверную классификацию невалидных DNS labels,
  отсутствия awk и малого nslookup. Все три исправлены с RED → GREEN тестами.
- Review owner-проверки выявил Int64 порта в современном PowerShell,
  недостающие сведения об awk/порте и недостаточную проверку ответа SSH.
  Исправлено; неверный адрес, усечённый и неожиданный ответ отклоняются.
- Offline runner PASS на Windows PowerShell 5.1 и текущем PowerShell:
  пустой список, один endpoint, неподдержанный runtime, неверный target,
  неполный/неожиданный ответ; реальный SSH не выполнялся.
- Packaging fixture закреплена на ранее принятом observer source `fb8d9e3`:
  старый тест предполагал ровно один Telegram delta и ломался от допустимого
  изменения DNS. Production allowlist и inventory не расширены.

Сборка установщика и LIVE Apply/Verify в этой работе не выполнялись.
