# Предварительная проверка DNS на CUDY

Владелец запускает `check-dns.ps1` в Windows. По умолчанию используются только
адрес и порт из уже существующего файла
`%USERPROFILE%/CUDY-Update-20261119-fb8d9e3/owner-session.json`.
Файл сеанса не меняется; этапы установщика не вызываются.

В исправлении r3 скрипт передаётся через стандартный ввод, а удалённая команда
содержит только `sh -s -- <профиль>`. Не нужны `base64` и длинная exec-команда.
Проверено через Windows PowerShell 5.1 и настоящий OpenSSH/Dropbear в одноразовом
локальном контейнере: старая команда отклонена, новая получила полный отчёт.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\check-dns.ps1
```

Если сеанс сохранён в другом месте, добавить `-SessionFile "полный путь"`.
Для другого профиля разрешён параметр `-Profile`, по умолчанию используется
известный проекту `acl_A2dNs`; это не автоматический поиск всех клиентов.

Проверка читает возможности BusyBox и разрешённые поля `dns-in` из generated
config текущего профиля. Сетевых DNS-запросов, изменения UCI/firewall, остановки
служб и установки файлов на роутер нет. Показанный endpoint — кандидат из
конфигурации, не доказательство живого listener или работающего интернета.
Полные конфигурации, ключи, адреса серверов и правила маршрутизации не выводятся.

Результат сохраняется в домашней папке Windows как `CUDY-DNS-Discovery-*.txt`.
Для продолжения разработки достаточно этого файла. Отсутствующий/неподдержанный
runtime — полезный результат исследования, а не команда чинить сеть.
При ошибке SSH показать текст ошибки; файл сеанса или резервную копию присылать
не нужно. Проверку выполняет владелец; агент к production CUDY не подключается.

## Стенд

`python3 -m unittest discover -s scripts/observability -v` — реальные BusyBox ash,
ucode и UDP resolver только на loopback в контейнере с `--network none`.
`test_runner.ps1` заменяет SSH локальной функцией и проверяет Windows PowerShell
5.1 и текущий PowerShell без реального соединения.
`test_transport.ps1 -CommandFile <путь>` захватывает команду через локальный
подставной `ssh.exe`; этот файл можно передать Linux-тесту через
`HG_DNS_TRANSPORT_COMMAND_FILE` вместе с соседним `.stdin` для проверки команды
и потока данных без настоящего SSH.

`test_dropbear_transport.py` — отдельная opt-in проверка Windows OpenSSH →
одноразовый Dropbear, только `127.0.0.1`. Переменная `HG_DNS_DROPBEAR_IMAGE`
задаёт локальный образ с dropbear/dropbearkey. Проверка генерирует отдельные
ключи и known_hosts, не читает настройки SSH или сеанс владельца и удаляет
свой контейнер после проверки. В обычной Linux CI она явно пропускается.

Внутренние `HG_DNS_PREFLIGHT_CONFIG` и `HG_DNS_TEST_ADAPTER` используются тестами;
при обычном owner-запуске они не задаются.
